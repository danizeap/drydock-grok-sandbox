## Decisions

| Date | Decision | Reason | Alternatives Considered |
| --- | --- | --- | --- |
| 2026-09-01 | Two instruments: tracked-set closure via `git ls-files` for "exactly six", filesystem presence (`rglob`) for the mutating four. | "This repo vendors six files" is a claim about committed contents, so git is authoritative; `__pycache__/` is on disk right now and a filesystem-only closure check would false-positive immediately. But an *untracked* `mutate.py` is fully runnable, so the ban must be about presence, not tracking — the Owner's words were "may not exist under `scripts/conductor/`". | (a) Filesystem-only for both — fails on `__pycache__` and dev scratch, gets turned off. (b) Tracked-only for both — an untracked `mutate.py` would sit there runnable with a green probe, which is the exact failure this packet exists to prevent. |
| 2026-09-01 | The mutating-four check is **repo-wide but tracked-only**; the filesystem scan stays scoped to `scripts/conductor/`. | The prose ban is "not vendored here", not "not vendored in one directory" — committing `scripts/mutate.py` is the same capability with the gate silent. Repo-wide over a listing already in hand costs one comparison per file. A repo-wide *filesystem* walk would traverse `.git/`, venvs and future `node_modules` on every probe run. | (a) Directory-scoped only — trivially evaded by vendoring one level up. (b) Repo-wide filesystem scan — slow, noisy, and false-positives on unrelated third-party vendored code. |
| 2026-09-01 | `CONDUCTOR_ALLOWED` is a hardcoded frozenset, kept in step with `drydock-pins.json` by a test (`test_allowlist_matches_pins`) rather than derived from it at runtime. | A gate that reads its allowlist from the artifact it gates widens itself the moment someone pins a seventh file. Two independent statements (pins: "these contents"; closure: "exactly these six") are defense in depth; a test catches drift between them loudly. | Deriving the set from `pins["files"]` at runtime — DRYer, but self-widening and therefore not a gate. |
| 2026-09-01 | The closure check does **not** report missing pinned files. | `check_pins()` (`scripts/start_probe.py:63-65`) already owns that failure mode. Duplicating it makes one fault print two errors in two vocabularies. Pinned by `test_missing_pinned_file_is_not_reported_here`. | Also failing on missing files "for completeness" — rejected as an invented second failure mode. |
| 2026-09-01 | `start_probe`, not `hooks/packet_guard.py`. | The guard's deny tier is migrations / new CI config / container config only (`hooks/packet_guard.py:105-128`), it silent-allows on error by design (line 16), it is a Claude Code PreToolUse hook that Grok Shell never invokes, and it governs write attempts rather than tree state. A closure invariant must be checkable after the fact by CI on any machine. | Adding a conductor deny class to the hook — leaves Grok Shell and CI ungated, and silent-allows on error. |
| 2026-09-01 | Untracked, non-mutating extra files under `scripts/conductor/` are accepted (do not fail). | Round 2 restatement: this is not a `__pycache__` carve-out but a consequence of the predicate — claim (a) is about what the repo *vendors*, and git is the authority on that. The four named runtime dangers are still caught by presence regardless of tracking; bytecode of a banned module *does* fail. Recorded as an explicit residual, and now also as **OQ-1** so the Owner can widen it knowingly. | (a) Failing on any untracked file — breaks on bytecode today. (b) `git ls-files --others --exclude-standard` — genuinely viable (empty on the current tree), git-declarative, but wider than the Owner's stated predicate, so it is offered as OQ-1 rather than taken unilaterally. |
| 2026-09-01 | Round 2 is the final negotiation round; the packet ships on the OQ defaults unless the Owner answers. | The cap is 2 rounds and round 1 did not converge. Leaving the packet blocked on three policy questions would convert a LITE guardrail into an open-ended design debate. Each OQ therefore has a default that matches the Owner's stated intent and a written delta for the alternative, so an Owner answer is an edit, not a re-plan. | Blocking implementation on Owner sign-off for all three — disproportionate for a LITE additive check whose defaults are exactly what the Owner asked for. |
| 2026-09-01 | **Implement-time:** where `plan.md` §7 item 3 contradicts `plan.md` §1, the code follows §1. `check_conductor_closure(tracked=['scripts/conductor/mutate.py'])` returns `[]`, not a `mutating conductor tracked:` error, when that file is not on disk. | §1's tracked loop `continue`s without appending for a banned stem *inside* `scripts/conductor/`, and §1 names that dedupe as something the implementer must not simplify away ("in-dir hits belong to the presence scan"). The presence scan then reports nothing because nothing was planted — planting is forbidden by `must_not_do` 1. So §7's expected output describes a behavior §1's own code does not have. The error class is real and reachable for a path *outside* the directory: `tracked=['scripts/mutate.py']` → `['mutating conductor tracked: scripts/mutate.py']`, run and pasted in `verification.md`. The in-directory tracked+on-disk case is covered by `test_banned_file_reported_once` under `tmp_path`. | (a) Dropping the `continue` so the in-dir tracked case also reports — rejected: it is an explicit must-not, and it makes one fault print three errors. (b) Planting `scripts/conductor/mutate.py` to make §7's command produce output — rejected outright: `must_not_do` 1. |
| 2026-09-01 | The Codex decomposition (five owner/tier-assigned subtasks) is not adopted. | This is one production file plus one test file; a five-way split with flagship/workhorse/cheap tiers costs more coordination than the change. Its one load-bearing item — "decide the exact policy first" — is adopted, as `plan.md` §0 and OQ-1..OQ-3. | Adopting the split as written — process weight disproportionate to a LITE packet. |
