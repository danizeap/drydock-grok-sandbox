| 2026-09-01 | Pass `**kwargs` through to `discover_core()` as the sole test seam, rather than injecting a fake `discover` callable. | Brief prefers the existing `path_env` / `home` kwargs; keeps tests exercising the real discovery code (incl. the `.sandbox-bin` exclusion) instead of a stub. | Injecting a `discover=` callable (tests would stop covering the real search); monkeypatching the module attribute (fragile against the lazy import). |
| 2026-09-01 | Import `discover_core` lazily inside the function, guarded by `except Exception`. | The probe must still report pin/hook/secret results if the vendored conductor is missing or broken; `codex_bridge` does `sys.path` work at import time. | Module-level import (a broken bridge would traceback the whole probe). |
| 2026-09-01 | `check_discover` returns `(errors, skipped_reason)`, and both `discover_errors` and `discover_skipped` are always present in the JSON (`""` = not skipped), placed after `pre_commit_errors` and before `hook_evidence`. | A bare `list[str]` cannot say "skipped" without a sentinel inside the error list, which would make the skip silent — the one thing the Owner ruled out; `check_hooks()` already returns a tuple, so the shape is house style. Always-present keys keep the JSON one shape in every run, so a human diffing local vs CI output never has to tell "key missing" from "did not skip", and an old probe is distinguishable from a new non-skipping one. Additive-only: verified no consumer parses this stdout (`.github/workflows/drydock.yml:24` uses the exit code only). | Sentinel string in `discover_errors` (silent skip); omit `discover_skipped` when absent (two JSON shapes, missing-vs-false ambiguity); a separate `discover_ok` boolean (redundant with `ok` and the error list). |
| 2026-09-01 | Also test `main()` end-to-end through stdout JSON (two tests, `capsys` + `json.loads`), stubbing the other five checks; the missing-core case relies on the autouse fixture's blanked env rather than stubbing `check_discover` itself. | Folds in Codex round-2's non-blocking gap: the `check_discover` unit tests alone never proved the `errors` sum, the `ok` flip, the exit code, or that the two new keys actually reach stdout.
